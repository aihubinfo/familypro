SuperGrok 把原来的多项每日限制调整为共享的 7 天配额后，Usage 页面上的“已使用 36%”反而带来了一个更直接的问题：一整周的 100%，究竟能生成多少图片和视频？

xAI 目前没有公布“每张图片扣多少、每个视频扣多少”的固定换算表。下面的数量来自官方规则、Usage 前后变化样本和简单反推，适合用来做一周预算，不应理解为官方保证。

> 数据核对日期：2026-07-24  
> 说明：Weekly Usage 会受任务类型、计算量、账号等级和后台策略影响，以下数量仅供参考。请以自己账号 Settings → Usage 页面显示的实时消耗和重置时间为准。

## 先看结论：一周大概能做多少

如果把全部周配额只用于一种任务，按目前较稳定的样本估算：

| 使用方式 | 单次估算消耗 | 一周参考数量 |
| --- | --- | --- |
| Speed 图片 | 约 0.125% | 约 700-800 张 |
| Quality 图片 | 约 0.25% | 约 350-400 张 |
| 480p、10 秒视频 | 约 1.27% | 约 70-80 个 |
| 720p、10 秒视频 | 约 2% | 约 45-50 个 |

真实创作一般不会只做一种内容。一个更接近实际的重度周预算是：

- 约 100 张 Quality 图片
- 约 20 个 480p、10 秒视频
- 约 10 个 720p、10 秒视频
- 剩余约 30% 留给聊天、提示词调整、重做、失败任务和临时需求

这套组合能覆盖风格探索、低清测试和高清成片三个阶段，比单纯追求极限数量更有参考价值。

## SuperGrok 的 7 天共享配额怎么扣

xAI 官方 FAQ 说明，付费 Grok 用户现在使用一个共享的 Weekly Usage 池。Chat、Imagine、Voice、Build 等产品不再各自拥有完全独立的每日次数，而是共同消耗这一周的额度。

Usage 页面通常会显示：

```text
Weekly Usage
Used: 36%
Imagine: 29%
Chat: 5%
Other: 2%
Remaining: 64%
```

不同功能并不是“一次扣同样的量”。普通聊天所需算力较少，高质量视频或长时间代码任务消耗更多。配额会按照 Settings → Usage 显示的时间每周重置，页面还会按产品拆分用量。

因此，真正需要估算的不是“官方允许多少次”，而是“同规格任务平均消耗周配额的百分之几”。

## 怎样从 Usage 百分比反推次数

测算时应尽量控制变量：使用同一账号，在较短时间内连续生成相同模式、分辨率和时长的内容，并记录生成前后的 Usage。

计算公式很简单：

`单位消耗 = Usage 增量 ÷ 完成数量`

`理论周数量 = 100 ÷ 单位消耗`

例如，一组近期用户端样本记录了 15 个 480p、10 秒视频，Usage 从 0% 增加到 19%：

`19% ÷ 15 ≈ 1.27%`

`100% ÷ 1.27% ≈ 79`

理论值约为 79 个。考虑页面百分比取整、后台策略变化、失败生成和其他功能占用，做预算时写成 70-80 个更稳妥。

这种方法比“某位用户一周做了多少个”更可靠，因为它至少排除了大量未知的聊天、画质和任务混用因素。不过它仍是特定时间与账号下的观察值，不是永久兑换率。

## 视频最消耗配额

视频是最需要提前规划的部分。几次高清测试就可能吃掉明显的周额度。

### 480p、10 秒：按 70-80 个预算

近期较有参考价值的样本是 15 个视频消耗 19%，平均每个约 1.27%。如果全部配额只用于这一规格，理论上约 79 个。

不同批次的用户也报告过更低或更高的单位消耗，说明后台并非固定次数表。因此，不建议把偶尔出现的峰值当成稳定产能。项目排期按 70-80 个计算更保守，平均每天约 10-11 个。

480p 更适合验证动作、镜头和提示词结构。先用它排除明显跑偏，再决定哪些方案值得进入高清生成阶段。

### 720p、10 秒：按 45-50 个预算

近期常见观察值约为每个 720p、10 秒视频消耗 2% 周配额。按这个比例，整周理论上约 50 个；考虑波动与其他任务占用，建议按 45-50 个做预算，平均每天约 6-7 个。

如果每个可用成片平均需要尝试 3 次，那么 45-50 次生成大约能筛出 15-17 个成片。若部分提示词一次成功，最终可用数量可能接近 20 个。这个数字比单看“能生成 50 次”更适合评估真实产能。

还有一层限制需要单独注意：xAI 官方 FAQ 明确说明，账号达到对应订阅等级的 720p 上限后，后续视频会自动回落到 480p。也就是说，即使总 Weekly Usage 还没有用完，也不代表可以继续生成同样数量的 720p 视频。

## 图片额度相对宽松

与视频相比，图片对周配额的压力小得多。

### Speed 图片：约 700-800 张

按“约 8 张 Speed 图片消耗 1%”的测试口径，单张约消耗 0.125%，全周理论上约 800 张。给后台波动留出空间后，700-800 张是更实用的预算范围。

平均到每天超过 100 张。除非进行大规模批量测试，多数个人创作者很难真正用满。

### Quality 图片：约 350-400 张

按“约 4 张 Quality 图片消耗 1%”计算，单张约消耗 0.25%，一周理论上约 400 张。考虑浮动后，可按 350-400 张预算，平均每天约 50 张。

如果每组可用结果需要生成 4 张候选图，一周 400 张可以筛选出约 100 组结果。对日常社媒配图、概念图和视频首帧探索通常已经足够。

### 不要用 API 价格硬算网页周配额

xAI 的 API 价格页显示，Quality 图片的 1K 输出为每张 0.05 美元，2K 为每张 0.07 美元。这个差价可以说明 API 侧的资源与商业定价不同，但不能直接推导 SuperGrok 网页端的 Weekly Usage。

API 按调用计费，SuperGrok 是订阅产品内的共享资源池。xAI 没有说明两套体系按固定比例兑换。因此，目前最多只能确认 Quality 模式通常比 Speed 模式更消耗配额，不能据此给网页版 1K 和 2K 编造精确百分比。

同样，不应使用 API 的 480p、720p 每秒价格直接换算订阅配额。API 资料适合用来确认更高分辨率需要更多资源，不适合当作 Weekly Usage 的兑换表。

## 混合使用怎样安排更合理

以一周内同时制作图片和视频为例：

| 任务 | 数量 | 估算消耗 |
| --- | --- | --- |
| Quality 图片 | 100 张 | 约 25% |
| 480p、10 秒视频 | 20 个 | 约 25.4% |
| 720p、10 秒视频 | 10 个 | 约 20% |
| 合计 | — | 约 70.4% |

剩余约 29.6% 可以留给提示词讨论、图片重做、视频失败、Moderation 拦截和临时任务。不要把计划排到刚好 100%，因为百分比显示有取整，失败任务是否产生消耗也可能随产品策略变化。

如果主要做视频，可以按下面的方式理解产能：

- 偏测试型：以 480p 为主，一周约 70-80 次。
- 偏成品型：以 720p 为主，一周约 45-50 次。
- 按每个成片平均尝试 3 次计算，一周可期待约 15-17 个较满意的 720p 成片。

如果主要做图片：

- Speed 模式一周约 700-800 张。
- Quality 模式一周约 350-400 张。
- 按每 4 张筛选 1 组可用结果计算，Quality 模式约能得到 90-100 组结果。

## 更省配额的工作流

最有效的策略不是少创作，而是把高成本生成留到最后：

1. 先用图片确认主体、构图、光线和整体风格。
2. 再用 480p 视频测试动作、镜头和提示词。
3. 只有方向确认后，才生成 720p 成片。
4. 每轮只调整一类变量，避免无法判断哪次修改真正有效。
5. 给一周配额预留至少 20%-30%，不要第一天就把高清任务排满。

按约 2% 一个计算，5 个 720p 视频就是约 10%，10 个就是约 20%。如果所有提示词都直接从高清开始测试，一天就可能消耗整周额度的很大一部分。

## 用自己的账号做一次小测试

由于 Weekly Usage 没有公开固定兑换率，最准确的办法仍是测自己的账号：

1. 等待周配额重置，记下初始 Usage。
2. 连续生成 10-20 次相同规格的内容。
3. 记录结束后的 Usage。
4. 用 Usage 增量除以完成次数，得到当前单位消耗。
5. 用 100 除以单位消耗，估算整周理论数量，再预留 20%-30% 缓冲。

例如，20 个同规格视频消耗 25%，单位消耗就是 1.25%，理论周数量约为 80 个。若同一测试在下周出现明显不同的结果，应以较新的数据更新预算。

## 最终结论

SuperGrok 的图片额度相对宽裕，真正需要规划的是视频。按 2026-07-24 的样本做预算，可以先记住三个范围：

- Speed 图片约 700-800 张，Quality 图片约 350-400 张。
- 480p、10 秒视频约 70-80 个。
- 720p、10 秒视频约 45-50 个，并注意可能先触发单独的 720p 上限。

这些数字的意义不是告诉你“最多能刷多少”，而是帮助你把测试、返工和成片安排进同一个 7 天周期。准备订阅前，也可以先查看 [FamilyPro Grok 套餐页](https://familypro.io/en/products/grok?invite=YK868462)，核对套餐期限、交付方式和当前规则。
